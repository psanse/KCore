The concept: k-cores

The k-core of a graph is the largest subgraph in which every vertex has degree at least k within that subgraph. The coreness (core number) of a vertex v is the largest k such that v belongs to the k-core. The maximum coreness over all vertices is the degeneracy of the graph.

Intuitively, a k-core is what is left after you repeatedly delete every vertex with fewer than k neighbours. Because deleting a vertex lowers the degree of its neighbours, the removal cascades — which is why the core number is more informative than the plain degree: a vertex with many neighbours that are themselves poorly connected still has low coreness.

Nested

The cores form a hierarchy: the (k+1)-core is contained in the k-core. The 0-core is the whole graph.

Bounded by degree

coreness(v) ≤ deg(v), and a graph with maximum core number k has a clique of size at most k+1.

Degeneracy ordering

Listing vertices by non-decreasing coreness gives an ordering where each vertex has at most k later neighbours — ideal for clique search and colouring.

The algorithm Batagelj & Zaversnik, 2003

KCore implements the bin-sort algorithm from An O(m) Algorithm for Cores Decomposition of Networks:

  1. Compute the degree of every vertex and bucket-sort vertices by degree.
  2. Repeatedly take the vertex v of minimum current degree; its coreness is that degree (never lower than the previous one).
  3. Remove v: every not-yet-processed neighbour with a higher degree drops one bucket. Bucket moves are O(1) swaps, so the whole run is O(|E|).

The order in which vertices are removed is the degeneracy ordering, also exposed by the library. The playground above runs exactly this process on your graph.

Usage

Include src/kcore.h. The class lives in namespace kcore and works on BitGraph graphs (namespace bitgraph).

#include "kcore.h"

bitgraph::ugraph ug{ 4 };            // star graph
ug.add_edge(0, 1);
ug.add_edge(0, 2);
ug.add_edge(0, 3);

kcore::KCore<bitgraph::ugraph> kc{ ug };
kc.find_kcore();                     // O(|E|)

int k = kc.max_core_number();                // 1
int c = kc.coreness(2);                      // 1
bitgraph::vertices s = kc.core_set(1);       // vertices in the 1-core

To decompose an induced subgraph, pass the vertex set to the constructor and call find_kcore(true):

bitgraph::vertices subgraph = { 0, 2, 3 };
kcore::KCore<bitgraph::ugraph> ksub{ ug, subgraph };
ksub.find_kcore(true);

KCore keeps a reference to the graph, which must outlive it and must not be modified while the object is in use.

API

MemberDescription
find_kcore(is_subgraph = false)Computes coreness and the degeneracy ordering, for the whole graph or the induced subgraph.
find_kcore(g) (static)Maximum core number in O(|V|²) via the width of a minimum degenerate ordering. Reference implementation.
find_kcore_UB(UB)Degeneracy ordering assuming UB is an upper bound of the core number. Full graph only.

Build

BitGraph and GoogleTest are fetched automatically by CMake (FetchContent); you only need a C++14 compiler and CMake 3.14 or later.

cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release        # run the unit tests

bin/Release/kcore path/to/graph.clq      # or run without arguments for a demo graph
